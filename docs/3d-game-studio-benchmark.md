# enV game and asset studio: research baseline

Research date: 29 October 2026. This compares documented workflows, not measured performance. No claim of superiority is justified until the same representative projects, hardware and user tasks have been tested across products.

## Established product workflows

| Product | Relevant baseline from the product documentation | Implication for enV |
| --- | --- | --- |
| Unreal Engine | The editor combines level editing, play controls and platform deployment. Its modeling mode includes mesh creation, sculpting, topology, UVs, multiple materials, collision and texture baking; Epic labels that mode beta. [Editor](https://dev.epicgames.com/documentation/unreal-engine/unreal-editor-interface), [modeling](https://dev.epicgames.com/documentation/unreal-engine/modeling-mode-in-unreal-engine) | A scene assembler alone is not a complete asset authoring studio. Mesh editing, non-destructive previews, materials and production packaging need real tools and tests. |
| Unity | Reusable Prefabs, animation and physics work inside a scene-based editor, with platform-specific builds and a cloud asset/build workflow. [Prefabs](https://docs.unity3d.com/Manual/Prefabs.html), [build automation](https://docs.unity.com/en-us/build-automation/overview) | Asset reuse, changes to instances, project history and reproducible builds are core workflows. |
| Godot | Node-based 2D/3D scenes, 3D model import, per-node import settings, material and animation previews, and platform export are integrated in the editor. [3D import](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/index.html), [advanced import](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/advanced_import_settings.html), [export](https://docs.godotengine.org/en/stable/tutorials/export/index.html) | Separate 2D and 3D workflows, explicit import options, source preservation, and testing every exported target are important. |
| Blender | glTF export supports geometry, materials, textures, lights, cameras, skinning and animation, with documented limits on which properties export. [glTF exporter](https://docs.blender.org/manual/en/5.0/addons/import_export/scene_gltf2.html), [modeling](https://docs.blender.org/manual/en/latest/modeling/index.html) | Test real textured and animated models, show unsupported extensions, and preserve source and import metadata. Authoring geometry, UVs, rigs and animation needs substantially more than a GLB loader. |
| Roblox Studio | Terrain, 3D assets, animations, physics, scripts, collaborative editing, testing and publishing form one connected workflow. [Creator tools](https://create.roblox.com/docs/get-started/tools), [terrain](https://create.roblox.com/docs/building-and-visuals/studio-modeling/terrain), [collaboration](https://create.roblox.com/docs/projects/collaboration) | A friendly experience needs onboarding, reusable content, creator permissions and collaboration alongside the editor, not just more buttons. |
| Substance 3D Painter | Texture baking and material painting are dedicated asset-production workflows. [Baking](https://helpx.adobe.com/substance-3d-painter/features/baking.html), [materials](https://helpx.adobe.com/substance-3d-painter/features/smart-materials.html) | A production material workflow needs texture maps, baking, previews and export fidelity; a color picker alone is insufficient. |

## Current enV state

The web editor has a 3D viewport, primitives, transform controls, validated self-contained GLB import, an Artboard image handoff, three scenes, local save/load, player collision movement and a verified browser export. A Godot source export reads the same project. Android has a native Godot preview integration; iOS has a native SceneKit preview integration in development. The UX/UI Artboard in this repository is a 2D design tool, and its 3D handoff is an image plane; it is not a 3D mesh authoring library.

The current project supports static scene objects and 2D Artboard images *inside* a 3D scene. Dedicated static and 2D game authoring modes, a comprehensive 3D modeling Artboard, complete native editors, production-grade animation, physics, interaction authoring, cloud collaboration, account-owned asset storage, and signed native game builds are not implemented. See [implementation status](./3d-game-studio.md) for the detailed list. None should be represented as complete until implemented and tested.

## Benchmark and release gates

Run the same documented tasks against enV and selected competitors: create a project; author or import a textured animated asset; place, group and edit objects; configure movement and interactions; save and reopen; collaborate; and create and run each supported build. Record task completion, errors, recovery, number of steps, accessibility and user feedback. Test static, 2D and 3D projects separately, with 3D as enV's default workspace.

Measure load and import time, frame-time p50/p95, memory and battery usage for small, medium and large scenes. Include low/mid/high Android phones, iPhone/iPad and desktop browsers; record device, OS, browser, engine version, project complexity and network conditions. Measure real touch and keyboard usage at portrait and landscape sizes, including large text and screen readers. The workspace should fit the available viewport without scroll, with accessible paged or context-specific panels.

Use glTF sample assets with static, textured, skinned and animated models; include malformed files, unavailable resources, large textures and version migrations. Validate edits, save/reopen, undo/redo, runtime behavior, exports and source references end to end on every claimed platform. Measure release package size, startup, crash rate and upgrade/recovery paths. These are required tests and targets, not results from a completed competitive benchmark.
