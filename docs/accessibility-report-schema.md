# enV Accessibility Report Schema — v1

This document describes the portable output generated by the markup-based accessibility checkers. It is intended for engineering handoff, QA review, and local report comparison.

## Web exports

When a user runs **Check** for Alt Text, ARIA, Focus State, Motion & Reduced Motion, Keyboard Navigation, or Form Accessibility, the web studio offers:

- **JSON**: a versioned object suitable for issue trackers and internal pipelines.
- **CSV**: one row per finding for designers and triage spreadsheets. Values are quoted; quotes are escaped; values that begin with spreadsheet formula markers are prefixed with an apostrophe.
- **Plain-text report**: a human-readable local report.

The static export does not automatically include the separate axe-core scan. The axe-core result can be downloaded as a separate text report. Every report states that it covers the snippet and does not certify conformance.

## Finding fields

| Field | Meaning |
|---|---|
| `id` | Stable rule/target key such as `env-a11y:aria/aria-value-expanded/button#primary-toggle`; identical inputs should produce identical IDs. Duplicate same-rule/target findings get an occurrence suffix. |
| `severity` | Current heuristic severity (`critical`, `serious`, `moderate`, `minor`). It is not a conformance verdict. |
| `rule` | Deterministic rule key useful for deduplication and regression tests. |
| `element` | Tag, selector, or target label inferred from source text. |
| `line` | Best-effort, one-based source line. It can be null when a static target cannot be uniquely mapped. |
| `evidence` | Up to a small source excerpt from the supplied snippet; it is not rendered-DOM evidence. |
| `relatedCriteria` | WCAG review areas potentially related to the pattern. These do **not** prove that a criterion failed. |
| `review` | `verify-in-context` for specific detectable patterns, otherwise `manual-review`. Neither status is a pass/fail certification. |
| `message` / `fix` | Reason for investigating and a suggested next step. Suggestions must be reviewed before applying. |

Top-level JSON includes `schemaVersion`, product/category, counts, findings, and limitations. Schema changes should increment `schemaVersion` when consumers would need code changes to read the report.

## Cross-platform behavior

TypeScript, Kotlin, and Swift keep their own rule engines. The engines use a parallel text-report contract: finding ID, target, source line where available, evidence excerpt, related WCAG review criteria, manual-review cue, and fix. This avoids routing native analysis through the web frontend.

The native engines currently analyze supplied source snippets. ARIA checks heuristically estimate accessible names for buttons, links, and custom controls from text, selected attributes, nested image/SVG names, and `aria-labelledby` targets that resolve to non-empty text/name hints; they are not full implementations of the Accessible Name and Description Computation specification. A lexical cross-platform gate guards the presence of key rule IDs and report fields but does not prove that every platform's behavior is identical for all HTML/CSS constructs. They do not inspect the whole running Android Compose/View tree or iOS UIKit/SwiftUI accessibility hierarchy. Real device-tree testing remains a separate future implementation phase.

## Security and trust notes

- Analysis remains local for these workflows; report export is initiated only by the user.
- CSV export neutralizes leading spreadsheet formula markers (`=`, `+`, `-`, `@`) in user-controlled cells.
- IDs are intended for cross-run triage, not cryptographic identity.
- Source excerpts may contain proprietary markup. Users should review the file before sharing it.
- A clean scan only means these selected static patterns did not match. It does not imply WCAG conformance.

## Additional rule introduced in iteration 4

- `target-size-risk`: a source-level review prompt for explicitly authored interactive target dimensions below 24 CSS px in width or height. Related criteria: `2.5.8 Target Size (Minimum)`. This is not a definitive WCAG failure because the static analyzer cannot calculate rendered bounds or spacing exceptions. Inspect the target in the actual rendered UI.
