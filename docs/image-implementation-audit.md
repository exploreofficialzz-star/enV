# enV Image category — implementation audit

Research/implementation date: 2026-09-29

This document records the migration against the supplied Image master brief. The catalog currently contains 185 Image entries, all routed through the shared image engine; catalog `active` is intentionally not treated as proof of completion.

## Implemented foundation

- `ImageDocument` / asset tracking model
- safe decode + dimension guards
- parameterized transform engine
- metadata inspection and true JPEG/PNG stripping
- capability-aware browser codec export
- target-size compression search
- composition/split/grid/contact-sheet helpers
- real ICO container builder
- manual mask/refine/redaction export path
- platform preset registry with source URLs/version metadata
- cancellable batch queue and per-file status
- provider abstraction for future segmentation/super-resolution

## System limitations that remain explicit

1. Dedicated HEIC/HEIF codec integration is not installed/configured. HEIC conversion therefore depends on actual browser decode capability and exports JPEG; no HEIC output is fabricated.
2. No learned background-segmentation model is configured. Background removal uses an honest manual mask workflow rather than a color-threshold heuristic or fake AI.
3. No learned super-resolution model is configured. The Upscaler tool requires the explicitly labeled high-quality resize fallback.
4. Browser worker/OffscreenCanvas execution is not yet wired end-to-end for every transform; decoded-pixel and batch safety limits are enforced in the shared core.
5. Full professional layers/adjustment-document undo history is scaffolded in `ImageDocument`, but the current editor surface is not yet a full Photoshop/Photopea replacement.
6. Platform presets are versioned and source-linked, but not every legacy catalog placement has been independently re-verified against its exact current official placement rules. Unverified/ambiguous concepts are disclosed rather than presented as universal platform facts.
7. Full cross-browser visual regression, fuzz, 24/48MP performance benchmarking, and production dependency installation remain release-gate work.

## Release-gate interpretation

The brief defines a tool as complete only when it validates inputs, runs a real parameterized algorithm, produces reopenable truthful output, handles errors/large inputs, meets accessibility/mobile requirements, has tests, and discloses limitations. The current branch closes the shared processing foundation and removes several fake/weak paths, but should still be treated as a migration build rather than a claim that all 185 tools have passed that complete gate.
