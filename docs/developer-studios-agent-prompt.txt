# Mission

Rebuild the Developer category (https://envtools.store/tools/developer — ~474 tools) using the **same Studio interface pattern** already proven on Accessibility (Color Contrast Studio, Alt Text Studio, ARIA Studio, Focus State Studio, Form Accessibility Studio, Keyboard Navigation Studio, etc.).

Goal: the Developer category must **stand out against the full systems** of CyberChef, DevToys, IT-Tools, jwt.io, regex101, crontab.guru, and privacy-safe alternatives to CodeBeautify/JSONFormatter — not free tiers only.

---

# Hard rules

1. **DO NOT remove any tool or URL.** Every existing `/tools/developer/*` slug stays live.
2. **Studios are the product surface.** Individual tool pages become focused entry points / modes of a parent Studio (deep-link with mode pre-selected), not empty one-field templates.
3. **100% client-side / on-device.** Nothing uploaded. Privacy is the primary competitive wedge (CodeBeautify/JSONFormatter server-side credential exposure is the industry cautionary tale).
4. **Match Accessibility Studio UX quality:** multi-mode workspace, clear job statement, privacy strip, examples, copy/download, precise errors, related modes, mobile-ready.
5. Web TypeScript first; engines structured so Android (Kotlin) and iOS (Swift) can share logic later.
6. Deterministic engines + golden tests for every Studio core path.

---

# Why Studios (standout comparison)

## Accessibility pattern to copy (enV already ships this)

Accessibility does not dump 55 thin pages as the hero experience. It leads with **named Studios**:

- Color Contrast Studio — WCAG 2.2 + APCA, vision simulation, export
- Alt Text Studio — severity, coach, bulk, export
- ARIA Studio — name/state, patterns, evidence
- Focus State Studio — :focus-visible, playgrounds
- Form Accessibility Studio — labels, errors, findings
- Keyboard Navigation Studio — order, traps, evidence

Each Studio is a **workspace**: modes, local processing, evidence-grade output, not “Input + Run tool.”

## Developer today (problem)

~474 tools: strong cores (JWT, Cron, Hash digests, UUID, Base64, improved JS/SQL format) + large template long-tail. SEO breadth is high; **workspace coherence is low** compared to Accessibility and compared to DevToys’ left-nav grouped toolkit.

## Competitor systems (what “stand out” means)

| Competitor | Full-system strength | Weakness enV Studios exploit |
|------------|----------------------|------------------------------|
| **CyberChef** | 300+ ops, recipe chains, client-side power | Steep UX; dated; poor mobile; overkill for one-shot |
| **DevToys** | Native offline, smart paste, grouped tools, consistent UI | Install required; desktop-first; no shareable deep links |
| **IT-Tools** | 80+ tools, good UX, self-host | Deploy/trust friction on public instances |
| **jwt.io** | JWT decode reference | Privacy anxiety; precision issues; single-purpose |
| **regex101** | Best live regex UX | Single-purpose |
| **crontab.guru** | Best English cron | Narrow |
| **CodeBeautify / JSONFormatter** | SEO catalog | Server-side history / credential exposure reports; ads |
| **ToolCove-class** | Clean client-side web toolkit | Smaller catalog |

**Standout formula for enV Developer Studios:**
- DevToys-like **grouped workspace** inside the browser
- Accessibility-like **Studio polish** (modes, evidence, privacy)
- CyberChef **power without recipe friction** for daily tasks
- Specialist **depth** (JWT safety, cron English, regex feedback) inside Studios
- CodeBeautify **breadth without server risk**
- Shareable URLs per tool/mode (DevToys cannot do this)

# Target architecture: Developer Studios

Implement **12 Studios**. Each Studio is a first-class route (like Accessibility studios) with mode tabs. Map every existing slug into a Studio mode or deep-link.

## 1. JSON Studio
**Route:** `/tools/developer/json-studio` (and keep all json-* pages as mode entry points)

**Modes:** Format · Minify · Validate · Diff · Path/Search · Tree (if feasible) · Convert (YAML/CSV when client-safe)

**Must-have:**
- Exact error line/position on invalid JSON
- Visible warning when integers exceed Number.MAX_SAFE_INTEGER (never silent mutation without warning)
- Duplicate-key behavior note
- Example fixtures + Copy/Download
- Privacy strip

**Maps from:** json-formatter, json-beautifier, json-minifier, json-validator, json-*, dummy-json-generator, developer-json-schema-generator, etc.

**Beat:** JSONFormatter.org (privacy), basic beautifiers (depth)

---

## 2. JWT Studio
**Route:** `/tools/developer/jwt-studio`

**Modes:** Decode · Expiration · Claims inspector · Payload builder · (Optional) Sign with user-supplied secret — clearly labeled

**Must-have:**
- Banner: “DECODE ONLY — signature not verified. Claims are untrusted.”
- Standard claims annotated (exp, iat, nbf, sub, iss, aud) with human-readable times
- Nested payload support
- Large-integer / precision note where relevant
- Privacy strip

**Maps from:** jwt-decoder, jwt-expiration-checker, developer-jwt-*, jwt-*

**Beat:** jwt.io on safety messaging + nested clarity + privacy

---

## 3. Regex Studio

- Common pattern presets

**Maps from:** regex-tester, regex-replace, developer-regex-*

**Beat:** approach regex101 feedback quality inside a multi-tool product

## 4. Hash Studio

**Maps from:** sha256-hash, md5-hash, sha1-hash, sha512-hash, hash-compare, file-hash-calculator, hash-*

**Beat:** single-algo sites; match DevToys multi-hash convenience

# Studio UI standard (copy Accessibility quality)

Every Studio page and every legacy slug page must include:

1. **Title + one-line job statement** (what it does + local/privacy)
2. **Privacy strip:** “Runs entirely on this device. Nothing is uploaded.”
3. **Mode tabs** (Studio) or clear primary action (legacy entry → Studio mode)
4. **Load example**
5. **Primary action** — Format / Decode / Hash / Match / Explain / Lookup / Generate…
6. **Copy + Download** on results
7. **Precise errors** — never silent fail
8. **Related modes / sibling tools** in same Studio only
9. **Mobile:** stacked panes, large targets, no horizontal editor trap
10. **Keyboard:** Ctrl/Cmd+Enter runs primary action
11. **No generic filler:** ban remaining “X utility for the enV toolkit” as sole description

Category index (`/tools/developer`) should lead with the **12 Studios** (like Accessibility leads with Studios), with “See more tools” still listing the long-tail mapped pages.
