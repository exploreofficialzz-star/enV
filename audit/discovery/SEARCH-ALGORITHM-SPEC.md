# Search algorithm specification (for Android/iOS parity)

Reference implementation: `src/lib/search.ts`. A native port is correct only if it returns the same ordered top-10 IDs as `audit/discovery/search-eval/native-golden.v1.json` for every case, over the same active catalogue. The legacy native substring/popularity scorers must be replaced, not wrapped. Android now uses `NativeCatalogSearch.kt` from `Catalog.webSearch`; iOS uses the equivalent indexed implementation in `CatalogCore.swift`. Both assistant candidate flows call the shared catalogue search instead of maintaining private scorers. Android `NativeCatalogSearchTest` and iOS `CatalogCoreTests.testNativeSearchMatchesTheCommittedWebGoldenQueries` compare the full ordered top-10 results against every record in `native-golden.v1.json`. These ports are implemented but remain unverified until authoritative native CI compiles and executes those tests.

1. **Normalize** text: Unicode NFKD, strip combining marks, lowercase, `&`→` and `, replace every character outside `a-z 0-9 % + #` and whitespace with a space, collapse spaces. Tokens are space-split pieces of length > 1 (or `%`).
2. **Stem** (same function for query and corpus): length ≤ 3 or any digit → unchanged. Plural pass: `(ses|xes|zes|ches|shes)$` → drop 2; `ies$` (len > 4) → `y`; trailing `s` dropped unless it ends in `ss`, `us` or `is`. Then drop the first matching suffix of `ion, ing, ers, er, or, ed, e` only if ≥ 4 characters remain.
3. **Fields and weights**: name 10, id 7, keyword 6, **alias 5**, tag 4, subcategory 4, category 3, description 2. Aliases come from `src/data/search-aliases.ts` (per-tool phrases); each alias is also indexed as one normalized phrase. A stem keeps its highest field weight per tool.
4. **Query terms**: drop stop words (list in source); if nothing remains keep all tokens. Each term has variants: exact stem (weight 1); reviewed synonyms (0.7, multi-word synonyms need all stems). The reviewed regular-expression vocabulary includes `regexp → regex` and `regular → regex`; the `regex-studio` alias phrases `test regular expression` and `regexp tester` route broad task intent to the multi-case Regex Studio. The legacy `regex-tester` record remains directly addressable by its exact name and ID. When the term's stem is absent from the whole corpus: typo candidates (Damerau-Levenshtein ≤ 1 for stems of length 4–8, ≤ 2 for ≥ 9; first letters equal or swapped; compared on surface and stem; best 3 by distance, then document frequency, then alphabetical; weight 0.55/0.4) and, only for the last term of queries of ≤ 2 terms, up to 8 prefix completions by document frequency (0.65).
5. **Term score** = best variant `weight × surfaceBonus(1 exact surface, 0.92 stem-only) × fieldWeight × idf`, `idf = ln(1 + N/(1 + df))`.
6. **Coverage**: `coverage = Σ idf of matched terms / Σ idf of all terms`. For ≥ 2 terms require coverage ≥ 0.75 (2 terms) or ≥ 0.6 (≥ 3 terms) and at least one match in a field of weight ≥ 4. Otherwise the tool is not a result.
7. **Score** = `Σ term scores × (0.4 + 0.6 × coverage)` `+30` if every term matched in name/id `+40` if the name contains the stop-word-free phrase `+20` if the name starts with it `+400` if name or id equals the query (id compared with spaces as `-`) `+250` if the stop-word-free phrase or the full phrase equals one of the tool's alias phrases `+60`/`-15` for a conversion query `A to B` (after removing a leading `convert|change|turn|transform|save`) whose name contains `A to B` / `B to A`, comparing with `jpeg→jpg` and `tif→tiff` normalized `-0.6 × min(4, extraNameTokens)` Round to 6 decimals.
8. **Order**: active/beta before planned; lexical score descending; popularity descending only when lexical scores tie; normalized name ascending; id ascending. Empty query: popularity descending with the same tiers and ties.
9. Search ranks metadata only. It never asserts that a tool works.
